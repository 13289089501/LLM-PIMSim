《10_版本更新记录》

项目：LLM-PIMSim
版本：v2（2026-08 增量版）
适用范围：v2/ 目录下全部代码与配置

本文件记录 v2 版本相对 v1 及此前 v2 早期版本的增量更新，
按"功能模块"分类，便于对照 01–09 号设计文档审阅。

========================================================
一、GUI 可视化拓扑编辑器（v2/gui_app.py）
========================================================

1.1 校验开关（可关闭）
- 后端 /api/run 新增 run_validation 参数；前端实验区新增勾选框
  「运行前校验」。取消勾选时跳过校验强制放行，默认开启。
- 用途：在配置暂不完整时快速试运行，不改变校验器本身。

1.2 新建实验
- 后端新增 /api/experiments（动态实验清单）、/api/experiment/create
  （新建实验）。新建实验会克隆所选模板的硬件/互连/映射/放置文件，
  自动生成带序号（NN_ 前缀）的独立实验入口。
- 前端实验下拉框改为动态加载，新增「＋ 新建」按钮与弹层
  （实验名 / 模型 / 克隆模板），创建后自动选中新实验。

1.3 弹窗交互修复
- 校验/结果弹窗、新建实验弹层均重构为「标题栏 + 右上角 × 关闭
  按钮 + 正文区」；标题栏可拖动，× 始终可见。

1.4 算子依赖关系图修复
- 修复多输入算子连线错误：
  * 每条数据依赖独立画线，去重键为（生产者, 数据名, 目标算子）；
  * 终点精确指向目标算子对应输入端口（按 inputs 序号定位端口 y）；
  * 起点连到生产者的对应输出端口；端口旁标注数据名；
  * 节点高度随端口数量自适应，避免重叠。

1.5 算子运行参考（推荐设备）
- 后端新增 /api/recommend 与 /api/reference：
  * /api/recommend 依据实验 mapping.yaml 规则给出每算子推荐设备；
  * /api/reference 生成完整参考（映射 + 数据流连线 + 互连链路），
    并用校验器验证，返回 valid/errors。
- 前端每个算子方块显示「推荐设备」；未手动拖拽映射的算子
  运行时会自动使用推荐设备。

1.6 可视化参考部署
- 点击「↻ 部署参考」或切换/新建实验时，自动把算子放入对应硬件
  方块内部（可点 × 叉出修改），并自动绘制数据流连线与互连链路。
- 修复 loadWeights 与 applyRecommendation 的异步竞态：
  改为 loadWeights().then(()=>applyRecommendation()) 串行执行。

========================================================
二、权重数据模型（v2/weights.py 新增）
========================================================

2.1 设计动机
- 原实现把权重当作算子的"输入字符串"，没有独立节点，导致：
  * 用户无法决定权重放在哪个硬件；
  * 依赖图缺少权重输入连线；
  * 权重真实大小被平均分摊，失真。
- 本版本把权重提升为一级数据节点 WeightBlock。

2.2 权重归类（按张量形状，不按算子）
  类别        成员（每层）            形状        可切维
  W_attn      q/k/v/o 四投影         各 [H,H]    沿 head 列
  W_mlp       ffn_gate/up/down       各 [H,·]    沿中间维
  W_ln        ln1/ln2 权重           各 [H]      通常不切
  W_head      lm_head（全局）         [V,H]      沿词表行
  W_embed     embed（全局）           [V,H]      沿词表行

2.3 数据结构
- WeightPartition：切分片（partition_id / rows / cols / bytes / device）
- WeightBlock：一类权重的实例（weight_id / weight_class / 形状 /
  bytes / consumers / input_slots / split_dim / partitions / device）
- 公开接口：
  * detect_weight_class(weight_name)      识别权重类别
  * build_weight_blocks(model, num_layers, h, f, nh, v, ...)
                                          生成完整权重块字典
  * _make_partitions(wb, n, devices)      按 split_dim 切分

2.4 切割语义（ALL-GATHER）
- 每类权重是"可切原子单元"；切割后每片可放不同设备；
- 需要该类的算子必须连接全部切分片才允许运行（见 W1 规则）。

2.5 悬空权重修正
- 移除 ffn_down_w 的硬编码消费者：workload 中 L0_ffn_down 的输入
  是 [ffn_up, ffn_silu]，不消费独立权重块，原硬编码导致 W1 误报。

三、校验规则（v2/constraints.py）
========================================================

3.1 新增 W1 权重完整性（ALL-GATHER）
- 规则：需要某类权重的算子，其权重输入端口必须覆盖该类权重的
  全部切分片（未切分=单逻辑分片=自身），缺任何一片即报 W1，
  阻止运行。
- 覆盖判定：来源端口能解析到某分片所在设备的读端口，或直接是
  该分片端口（含 {pid}_r / {pid}_w / {pid}），视为读到该分片。
- 错误示例：
  * 未切分：「算子 X 需要权重 W，但其权重输入端口未连接到该权重
    的存放设备。」
  * 已切分：「算子 X 需要权重 W 的完整内容，却只连接了部分切片
    —— 缺少 …。必须连接全部 N 个切片（ALL-GATHER）…」

3.2 校验器结构修正
- _port_exists：权重 id / 分片 id 视为合法端口主体（base in
  weight_ids）。
- D1 可达性：权重端口不参与硬件级链路检查（权重完整性由 W1 负责）。
- C1 容量：权重端口不按"算子数据"重复计入硬件容量。

3.3 C1 权重容量修复（本轮重点）
- 原缺陷：权重字节从不计入所在硬件容量，导致"GPU 8GB 塞下全部
  权重"等荒谬配置错误通过校验。
- 修复：
  * _normalize 记录权重 bytes / part_bytes / num_layers；
  * _rule_C_capacity 新增权重统计：每个权重块 bytes × 全模型层数
    计入所在硬件；真切割时按分片各自 device 计；
  * 前端 collectWeightBlocks 输出 bytes / num_layers。
- 验证：
  * GPU 8GB 全塞（权重×32层）→ C1 拦截（10.4GB > 8GB）；
  * GPU 80GB 全塞 → 通过（合理）；
  * IC 三设备方案 → 通过。

四、调度器 ALL-GATHER（v2/scheduler.py, engine.py, experiment_runner.py）
========================================================

4.1 Scheduler
- 新增 weight_shards 参数：{weight_data_id: {partition_id: device}}。
- _check_ready_ops：权重分片输入必须所有切分片都在其所在设备就绪

- result.metadata 记录 weight_shard_count。

五、前端权重块（v2/gui_app.py 内嵌 JS）
========================================================

5.1 权重块节点
- 后端新增 /api/weights：按模型维度生成第一层 WeightBlock 列表
  （与前端画布只显示 layers[0] 的算子对应），支持
  split=W_mlp:2 实时切割；每个块带默认设备建议 + bytes + num_layers。
- 前端加载模型后自动渲染权重块（紫色，显示类别/形状/大小/
  消费者数），默认按推荐设备自动放置。
- 拖拽入硬件 = 决定权重放置；可点 ✂ 切割输入片数切成 N 片。

5.2 权重端口
- 权重块渲染端口：未切割 1 个读端口 {weightId}_r；切割后每个
  分片一个端口 {partition_id}_r（垂直排布，标片号）。
- syncWeightConns 从权重端口出发连到消费算子的输入端口，
  权重是否被连接一目了然；连线带 _autoW 标记便于清理。

5.3 依赖图
- 新增最左侧紫色"权重源节点"列 + 紫色权重→算子边，
  解决"权重输入缺线"问题。

5.4 其他修复
- 参考连线应用时跳过权重输入线（统一由权重端口线负责），
  避免"很多同名权重"重复；
- drawConnections 跳过不可见端口（算子折叠进硬件 display:none 后
  不绘制，避免残留线）；
- groupOpToHW / detachOp 折叠/展开后触发重绘；
- deleteBlock 删除硬件时自动解除其上权重块。

六、IC 参考方案落地
========================================================

6.1 设计原则（集成电路视角）
- 权重跟计算走：哪类算子在哪个设备算，其权重就放那个设备；
- 按算术强度分设备：GEMM（高算术强度）→ GPU/PIM；
  逐元素/归约（带宽受限、精度敏感）→ SRAM-PIM/CPU；
- 中间结果就地存放，跨设备才搬运。

6.2 算子参考放置
  设备        算子                                           依据
  GPU         q/k/v/o_proj、attn_qk、attn_av（attention GEMM）
                                                            权重小、数据流内聚
  DRAM-PIM    ffn_gate/up/down、resid2、kv_update            权重最大、就地计算
  SRAM-PIM    ln1/ln2、softmax、ffn_silu                     归约/逐元素、高带宽

6.3 权重参考放置
  W_attn（q/k/v/o）→ GPU；W_mlp（ffn 三权重）→ DRAM-PIM；
  W_ln（ln1/ln2）→ SRAM-PIM；W_head/W_embed → RERAM-PIM。

6.4 中间结果放置
- 中间结果停在生产它的设备；只有跨设备算子边界才搬运小尺寸激活
  （score/probs 在 GPU↔SRAM 间搬、resid1_out 跨一次到 SRAM、
  ffn 输出全在 PIM 内部闭环）。

6.5 互联
- GPU↔SRAM、GPU↔PIM、PIM↔SRAM 全双工（热路径高带宽，参考默认 120GB/s）。

6.6 默认硬件
- configs/hardware.yaml 新增 SRAM-PIM（sram0，128MB/4000GB/s，
  LN/Softmax 效率高）；前端 init 自动加载 GPU + DRAM-PIM + SRAM-PIM。

十、已知边界与后续建议
========================================================

- 前端画布只渲染第一层算子/权重，容量校验按全模型层数放大
  （num_layers），供参考评估；多层的逐层细节暂不展示。
- KV cache 容量尚未按 decode 步长动态计入 C1（当前用算子静态
  memory_bytes_range 近似）。
- 权重的分片级独立放置（每片拖到不同硬件）已具备数据链路，
  前端交互目前为整块放置 + 切割展示。
