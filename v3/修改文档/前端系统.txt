== 背景约定（重要）==
- 后端（算子系统 core/operator_sys）仍按"逐层展开"生成算子：32 层 × 每层 16 算子 + 2 全局
  = 514 个算子，每层算子 id 带 L0_/L1_/… 前缀。这是后端既定行为，**本轮不改成"单层模板"**。
- 前端要解决的是：用户在画布上被 514 个算子 + 每层重复的算子块淹没，负担太重。
- 因此目标：**仅在前端做"层折叠/聚合"，后端不动**。

== 需求 1：算子按层折叠展示（减轻用户负担）==
用户诉求原文：32 层模型，不对每一层重复算子做重复建模；重复算子在画布上希望折叠起来，
需要时再展开。后端保持按层展开，前端用"层视图"掩盖重复。

初步构想（供后续确认）：
1. 画布默认只显示"一层模板"的算子（例如 L0_*），其余 31 层折叠为一个或几个"层组"容器。
   - 层组容器显示"层数 × N 层"，例如 `L1-L31`；展开时逐层列出，或仅显示某几层的代表算子。
2. 折叠后的"层"仍把 32 层当作整体参与连线/放置决策（说明：这只影响画布显示，不影响后端
   514 算子与结果/校验）。
3. 交互：点击层组可展开/收缩；"应用到全部层"可把一个算子/权重块的摆放批量复制到其余层。
4. 权重块类似：权重按 类×层 生成，前端同样按层折叠（每类每层一块 W_mlp 等）；可见时可看到
   各层的权重，折叠时归并显示类别与层数。

== 需求 2：参数范围 / 动态算子展示 ==
（承接算子系统"动态参数显示范围"的诉求，前端在展示时用 [min,max] 而非定值。）
- 对 KV 相关算子（随 kv_len 增长），前端显示其计算/存储的范围，而不是单个代表值。
- 需要后端输出系统在 /api/workload、/api/run 等返回里带上 compute/memory 的范围（输出系统已
  在 Workload/Kernel 层有 min/max，前端配合消费即可）。

== 需求 3：第一层实时校验（拖动/放置时边摆边提示） ==
（来源：校验系统 doc 的"双层校验"规划，这一层是前端待办。）
- 目标：用户在拖动算子/放到设备时，前端实时提示，而不是等全部连完才报错。
- 例子：把一个大算子拖进小容量设备 → 前端直接不让放 / 弹出提示并标红；把不能在该设备执行的
  算子拖进去 → 立即提示。
- 覆盖（复用后端校验接口的子集）：A1/A2/A3/A4（算子-硬件兼容）+ C1 粗略容量判断。
- 支撑：后端有 validate_config（core/validator），建议再补一个 validate_layer1(...) 或返回
  code 子集，前端在拖动回调里调用做阻塞提示。
- 处理：交互用"弹出 + 标红"；错误的放置不落盘（或标红待处理）。

== 需求 4：算子依赖图（DAG 展示） ==
（来源：校验系统 doc 的第 4 点，前端待办。）
- 目标：前端展示一张算子依赖图，让用户一眼看清"某算子的输入来自哪个算子的输出、输出喂给谁"，
  不用挨个端点点连线。
- 数据支撑（后端已有）：每个算子的 inputs/outputs（数据 id）、数据对象的 producer_op/consumers、
  /api/workload 能返回 id/inputs/outputs。前端据此组 DAG 边：[producer]→[consumer]，可带端口标签。
- 展示：独立抽屉/弹层，按层分组；点击某算子高亮其上下游；叠加权重源节点（紫色/`_r` 端口）便于
  看清权重流。

== 需求 5：关键路径视图（来自调度系统 doc 改进点 1，已确认）==
- 目标：运行后展示"决定总延时的关键路径"——从输入到输出耗时最长的那串算子链，标出每个算子的
  耗时构成，让用户一眼看到"卡在哪条链、是谁牵制"。
- 数据支撑（后端已实现）：core/exporter.build_critical_path(result) 已实现并随结果返回
  result['analysis']['critical_path']（算子序列 + 每节点 compute/local_rw/transfer/sync 构成 +
  解释文字）；GUI /api/run 也返回 critical_path。前端消费即可。
- 展示：可复用依赖图(DAG)抽屉，叠加"关键路径高亮"与"总延迟占比"；或独立的结果面板区域。
- 关联：输出系统.txt"关键路径归因"待办。
