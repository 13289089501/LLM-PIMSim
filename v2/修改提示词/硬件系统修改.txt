你是一个硬件性能参数配置专家。我们正在为 LLaMA-7B 推理模拟器校准硬件参数，目标是让模拟延时更接近真实设备。请严格按以下信息修改硬件参数定义，但不要改变现有计算逻辑和调度逻辑。

## 背景
模拟器通过 `performance.py` 计算每个算子的延时，核心公式：
- `T_compute = FLOPs / (PeakFLOPS * efficiency)`
- `T_local_rw = latency_ns + data_size_bytes / bandwidth`
调度器负责累加 compute、local_read、local_write、transfer、sync 五类时间。

当前支持五种硬件：CPU、GPU、SRAM-PIM、DRAM-PIM、ReRAM-PIM。
本次任务只更新硬件的峰值算力、存储容量、读带宽、写带宽、读延迟、写延迟、支持精度。**算子效率表暂不填写，等待后续任务。**

注意：
- CPU 的 45.9 TFLOPS 是 BF16 AMX 峰值；如果代码只支持单一 peak_compute_flops 字段，请填该值。若支持多精度多峰值，请保留其他精度峰值。
- GPU 的 312 TFLOPS 是 dense BF16/FP16 Tensor Core 峰值，不含 sparsity。
- SRAM-PIM 的 1.5 PB/s = 1,500,000 GB/s，请勿误写为 1500 GB/s。
- DRAM-PIM 按单个 stack 填写；若一个设备包含多个 stack，请在注释中说明并保持当前配置为单 stack 代表值。
- ReRAM-PIM 读写不对称，必须严格区分读带宽/写带宽、读延迟/写延迟。

## 单位处理要求
1. **峰值算力**：如果现有字段单位为 FLOPS/s，请将 TFLOPS 乘以 1e12；如果单位为 TFLOPS，则直接用数值。
2. **带宽**：如果现有字段单位为 bytes/s，请将 GB/s 乘以 1e9；如果单位为 GB/s，则直接用数值。PB/s 先换算为 GB/s 再按上述规则处理。
3. **容量**：按表中单位填写（GB 或 MB）；如果代码需要 bytes，请转换为 bytes。
4. **延迟**：统一使用纳秒 ns；如果代码字段是秒，请乘以 1e-9。
