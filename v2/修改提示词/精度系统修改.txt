==================================================

- BF16
- FP16
- FP8

不要添加：

- FP64

不要简单设计为：

FP16.value = 16

然后只依赖 bit width 判断兼容性。

请使用统一的 Precision 枚举或等价数据结构，并保留良好的扩展能力。

当前 6 种 Precision：

FP32
BF16
FP16
FP8
INT8
INT4

- data_precision
- execution_precision

但 execution_precision 额外允许为 None。

None 不是一种 Precision。

不要创建：

- N/A
- NONE
- UNKNOWN

等假的 Precision 枚举值。

==================================================
三、Operator 双精度字段
==================================================

所有 Operator 必须具有：

- data_precision
- execution_precision

语义固定如下：

data_precision：

表示算子处理和产生的数据精度。

execution_precision：

表示算子实际执行计算所要求的计算精度。

两者必须独立：

data_precision != execution_precision

是允许且正常的情况。

例如：

data_precision = FP16
execution_precision = FP32

是合法的。

execution_precision 的类型概念上应为：

Precision | None

但请根据项目实际 Python 版本选择兼容写法。

对于纯数据访问/更新型算子：

execution_precision = None

当前只有以下两个算子固定使用 None：

Embedding
KVUpdate

==================================================
十、兼容性判断规则
==================================================

一个 Operator 只有同时满足以下条件，才能映射到 Hardware。

------------------------------
条件 1：Category Compatible
------------------------------

operator.category

必须属于：

hardware.supported_operator_categories

即：

operator.category
in
hardware.supported_operator_categories

------------------------------
条件 2：Data Precision Compatible
------------------------------

operator.data_precision

必须属于：

hardware.supported_data_precisions

即：

operator.data_precision
in
hardware.supported_data_precisions

------------------------------
条件 3：Execution Precision Compatible
------------------------------

如果：

operator.execution_precision != None

则：

operator.execution_precision
in
hardware.supported_execution_precisions

必须成立。

--------------------------------------------------
普通计算算子最终规则
--------------------------------------------------

Can Execute
=
Category Compatible
AND
Data Precision Compatible
AND
Execution Precision Compatible

--------------------------------------------------
execution_precision = None 的算子
--------------------------------------------------

对于：

Embedding
KVUpdate

规则为：

Can Execute
=
Category Compatible
AND
Data Precision Compatible

不要检查 execution_precision。

==================================================
十一、精度或类别不兼容时的处理
==================================================

如果 Hardware 与 Operator 不兼容：

- 不允许映射。
- 不允许加入该设备的执行队列。
- 不允许作为调度候选设备。
- 返回明确失败结果，或抛出明确异常，具体遵循现有项目风格。

错误信息或失败原因应尽可能明确指出：

1. Operator 名称。
2. Operator Category。
3. Operator data_precision。
4. Operator execution_precision。
5. Hardware 支持的 Categories。
6. Hardware 支持的 Data Precisions。
7. Hardware 支持的 Execution Precisions。
8. 具体是哪一项不兼容。

例如：

Category incompatible

或：

Data precision FP8 is not supported

或：

Execution precision FP32 is not supported

不要只返回：

False

而完全无法得知失败原因。

可以设计：

can_execute(operator) -> bool

同时提供：

check_execution_compatibility(operator)

返回详细结果。

也可以使用现有项目更合适的结构。

但所有映射和调度前的合法性判断必须最终复用同一个核心兼容性逻辑。
