《03_数据模型与数据放置模块设计文档》

项目：LLM-PIMSim
模块：Data Model & Data Placement Model（数据模型与数据放置模块）
版本：v1.0

1. 模块概述
1.1 模块目的

Data Model负责描述LLM推理过程中产生和使用的所有数据对象。

Data Placement Model负责决定：

数据存储在哪里，以及数据如何随着计算过程在不同硬件模块之间移动。

该模块是LLM-PIMSim中非常核心的组成部分。

原因：

对于LLM-PIM系统而言，性能差异往往不是来自：

算子计算量不同

而是来自：

数据在哪里，以及数据是否需要移动。

例如：

同一个FFN算子：

方案A：

Weight

↓

DRAM-PIM

↓

DRAM-PIM Compute

无需搬运权重。

方案B：

Weight

↓

DRAM

↓

GPU

↓

Compute

需要：

权重读取
数据传输
写入GPU

两个方案计算量完全相同，但执行时间可能完全不同。

因此：

Data Model是连接：

LLM模型
Hardware Model
Performance Model
Scheduler

的核心桥梁。

3. 设计目标

本模块需要解决以下问题：

3.1 数据是什么？

例如：

模型权重
激活值
KV Cache
中间计算结果
3.2 数据在哪里？

例如：

Attention Weight

→ GPU HBM


FFN Weight

→ DRAM-PIM


KV Cache

→ SRAM-PIM
3.3 数据什么时候可用？

例如：

Q Projection

完成时间：

5ms

那么：

Q数据：

ready_time=5ms

Attention不能提前开始。

3.4 数据是否需要移动？

例如：

当前：

Weight:

DRAM-PIM

计算：

GPU

则：

产生：

DRAM-PIM → GPU

Transfer Event

KV Cache增长

↓

形式。

Data Object表示：

系统中任何可以被算子读取或产生的数据实体。

例如：

Hidden State

    name

    type

    size

    shape

    precision

    location

    ready_time

    producer

    consumers

唯一编号。

模块之间引用。

6.2 name

数据名称。

例如：

6.3 type

表示数据类别。

7. 数据类型设计
7.1 Weight（模型权重）

特点：

生命周期长
大容量
多次复用

例如：

Transformer Layer:

Wq

Wk

Wv

Wffn1

Wffn2

Weight是PIM系统最重要的数据类型。

因为：

PIM优势主要来源：

权重驻留（Weight Residency）

7.2 Activation（激活数据）

特点：

生命周期短
随计算产生

例如：

Q

K

V

Attention Output

FFN Input

7.3 KV Cache

特点：

Decode阶段不断增长
需要频繁访问

是LLM推理特有的数据。

7.4 Temporary

临时中间结果。

例如：

Attention Score

Softmax Buffer
8. 数据大小模型

Data Object必须记录：

size

单位：

Byte

计算：

Size=Number of Elements×Precision Size

例如：

FP16：

2 Byte

INT8：

1 Byte

为了支持LLM算子计算：

需要保存：

例如：

[hidden, hidden]

Shape主要用于：

后续：

FLOPs计算

Data Object需要记录：

数据自身精度。

例如：

FFN Weight

原因：

数据精度影响：

数据大小

例如：

FP16:

2Byte

INT8:

1Byte
硬件兼容

例如：

INT4 Weight:

可以进入：

但FP16：

可能不支持。

11. Location（数据位置模型）

这是本模块最重要属性。

定义：

表示：

当前数据所在Hardware Unit。

例如：

12. 数据位置变化

数据位置不是固定的。

例如：

初始：

GPU HBM

执行：

↓

13. Ready Time模型

每个Data Object维护：

表示：

数据最早可以被使用的时间。

例如：

ready_time=5ms

表示：

5ms之前：

其他算子不能读取Q。

17. 为什么需要用户指定Placement？

因为：

不同论文核心贡献就是：

例如：

论文A：

论文B：

KV Cache on SRAM

模拟器应该允许用户自由探索。

19. Weight Residency模型

之前定义：

Weight residency = true/false

现在升级。

Weight Residency由：

Data Location

+

Operator Mapping


共同决定。

例如：

情况1：

FFN Weight:

DRAM-PIM


FFN Compute:

DRAM-PIM


结果：

Weight Residency = YES

情况2：

FFN Weight:

DRAM-PIM


FFN Compute:

GPU


结果：

Weight Residency = NO

需要transfer
20. 数据移动触发机制

Data Model本身不计算传输时间。

它只负责：

发现：

source location

!=

destination hardware


然后通知Scheduler：

需要：

Transfer Event

流程：

Operator Ready

       |

Check Input Data

       |

Data Location == Compute Location ?

       |

   /       \

 YES       NO

  |         |

Execute   Transfer Event

21. KV Cache特殊模型

KV Cache区别于普通数据：

它会动态增长。

21.1 KV Cache生命周期

Decode过程：

每生成一个token：

new K

+

new V


加入缓存。

21.2 KV Cache对象

定义：

KVCacheObject

继承：

DataObject

增加：

current_sequence_length

max_sequence_length

growth_rate

22. KV Cache大小计算

公式：

KVSize=2×Layers×SeqLength×Hidden×PrecisionSize

例如：

生成token增加：

SeqLength:

1000

↓

1001


则：

KV Cache:

重新计算。

23. KV Cache位置影响

例如：

Decode：

Attention需要KV。

如果：

KV Cache:

SRAM-PIM

则：

访问快。

如果：

KV Cache:

CPU Memory

则：

需要大量搬运。

28. 模块总结

Data Model解决：

“数据是什么？”

Data Placement解决：

“数据在哪里？”

Scheduler解决：

“什么时候可以使用？”

Performance Model解决：

“使用需要多久？”

四者共同形成：

LLM-PIMSim的数据驱动执行模型。

本模块核心设计总结
功能	负责模块
描述数据	Data Model
记录数据位置	Data Model
决定初始位置	Data Placement
判断是否需要搬运	Data Placement + Scheduler
计算搬运时间	Performance Model
处理等待	Event Scheduler
分析收益	Bottleneck Analyzer
